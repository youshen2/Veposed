# 验证层级与交付

## 静态层

运行技能 `check_profile.py`，验证 AP 身份、Hook 文件偏移和运行地址对应、可写别名、16 字节签名、Thumb 位、命名点契约和堆别名长度。它还使用 `rustc` 编译当前运行时的 Thumb 跳板规划器与内存策略，检查全部内联入口能否生成跳板，以及目标与命名点的非零状态槽是否处在运行时允许的地址范围。检查不会执行跳板，也不会证明函数名称、调用原型、BSS 对象生命周期或 RAM 当前可用性。

从生成头文件抽查新增符号，核对平台源文件中使用到的每项。别名恢复要用启动代码证据交叉验证；相邻版本固定偏移不能作为唯一来源。

## 主机与构建层

```sh
cd "$REPO"
make check LUA="$LUA"
python3 vep.py suite --firmware "$FIRMWARE" --profile "$PROFILE"
python3 vep.py inspect-face "$FACE"
```

固件/平台变更后检查 Rust 内存范围和 C 缓存测试；UI ABI 变更检查 descriptor 大小/偏移断言。验证 ARM ELF32 ET_REL、soft-float、未解析导入为空，重定位属于目标 modlib 支持集合。构建失败必须修复根因，不能删除断言换取通过。

在模拟器中可只调用独立函数片段、检查目标地址和 copy/cache 逻辑。先补齐依赖段和 MMIO stub；明确哪些功能未模拟。模型返回成功不能充当实际 watchdog、文件落盘或设备字体的证明。

## 设备探针层

在用户已授权的设备操作范围内执行。若本次任务只有离线逆向，则交付探针和说明，不能自行刷写、重启设备或开展超出授权的实验。

顺序从低影响开始：身份与只读符号 → runtime/驱动/恢复管理器 → 可逆函数指针自测 → 单一有作用域的命名 Hook → 模块启停与页面刷新。每一步记录 hash、状态文件、触发方式和观察；出错停止后续注入，保留可恢复入口。

核验首次启动、Hook 失败回滚、未结束会话的下次启动隔离、手动重置后加载。断电与硬故障试验需要相应设备操作授权及可恢复条件，不因“完整验证”默认执行破坏性实验。

## 发布结果

交付 target JSON、evidence、平台差异、构建报告和安装 `.face`；附适配范围、验证层级、未决项与恢复方法。实际设备尚未运行时用 `device_validation: pending`。旧适配文件与既有行为保留；新增版本独立可选择。

`gitignore` 应排除原始固件、分析数据库、构建缓存和发布产物；将可复现脚本、源代码、适配表、短证据和技能纳入源码。源码包需有链接脚本、Rust 锁文件与构建配置，解包后使用外部提供的精确固件即可重建。
